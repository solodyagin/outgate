# Именование коммитов

Используй формат Conventional Commits: `type: описание` или `type(scope): описание`. Тип и необязательную область пиши строчными латинскими буквами; область должна обозначать затронутый модуль, например `sdk`, `protocol`, `gateway`, `routing`, `auth`, `quic`, `wss` или `docs`.

| Тип | Когда использовать |
| --- | --- |
| `feat` | Новая функциональность |
| `fix` | Исправление ошибки |
| `docs` | Изменения только документации |
| `style` | Форматирование кода без изменения поведения; не изменения внешнего вида интерфейса |
| `refactor` | Изменение структуры кода без новой функциональности и исправления ошибки |
| `perf` | Улучшение производительности |
| `test` | Добавление или изменение тестов |
| `build` | Изменения системы сборки или зависимостей |
| `ci` | Изменения CI/CD: конфигурации и сценариев автоматизации |
| `chore` | Прочие задачи сопровождения, не относящиеся к перечисленным типам |
| `revert` | Отмена предыдущего коммита |

- Выбирай тип по результату изменения. Исправление отображения интерфейса — `fix`, новая возможность интерфейса — `feat`; `style` используй только для форматирования исходного кода.
- Пиши краткое, конкретное описание по-русски, начиная с глагола в неопределённой форме, без точки в конце. Не используй общие сообщения вроде `fix: правки` или `chore: обновления`.
- Объединяй в одном коммите одну логическую задачу. Сопутствующие тесты и документация входят в коммит с типом основного изменения.
- При несовместимом изменении контракта добавляй `!` перед двоеточием: `feat(api)!: описание`. В теле сообщения после пустой строки добавляй `BREAKING CHANGE: ...` с описанием несовместимости и необходимых действий для перехода.
- При необходимости поясняй причину и детали в теле сообщения после пустой строки. Для `revert` указывай в теле хеш отменяемого коммита.

Примеры:

```text
feat(protocol): добавить проверку control-сообщений
fix(protocol): отклонять переполнение u64 при разборе
docs: описать правила работы кодового агента
refactor(sdk): выделить проверку префиксов
test(protocol): проверить усечённые WSS-сообщения
build(sdk): зафиксировать версию Go
chore: исключить временные файлы редактора из Git
```
